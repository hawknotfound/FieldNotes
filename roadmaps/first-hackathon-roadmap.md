# First Hackathon Roadmap

Go from "I have never been to a hackathon" to "I successfully participated in one."

**Who this is for**: Students who have zero hackathon experience. You may not know how to code. You do not have a team. You are doing this mainly to learn.

## Phase 0: Mindset (Before anything else)

Set expectations now to avoid disappointment later.

**Realistic outcomes from your first hackathon:**
- You will build something small, probably broken, definitely not production-ready
- You will learn more in 24-48 hours than in a month of self-study
- You will meet people who are at your level or ahead of you
- You may not sleep well. You will be tired. That is normal.
- You probably will not win. That is fine.

**Unrealistic outcomes to ignore:**
- Building a startup idea that gets funded
- Getting a job offer from a sponsor
- Being the best team there

Your only goal: finish something and submit it.

## Phase 1: Decide your role (Week 1)

### If you can code at all

You need one language/framework at a basic level. Pick whichever you already know:
- **Python**: easiest to start with. Flask or Streamlit for web apps.
- **JavaScript**: most flexible. React or vanilla JS for web apps.
- **Don't know any**: learn enough Python in 1 week. Variables, functions, APIs, request library. That is enough.

### If you cannot code

There are valuable non-coding roles in any hackathon:

| Role | What you do | Why teams need you |
|---|---|---|
| Designer | UI/UX, Figma mockups, presentation design | Every team needs visual design |
| Presenter | Pitch delivery, demo coordination, Q&A handling | Judges decide on presentations as much as code |
| Researcher | Domain research, competitor analysis, user validation | Teams often build without understanding the problem |
| Project manager | Task tracking, timeline management, communication | Teams collapse without coordination |
| Content writer | Problem statement framing, pitch deck content, documentation | Clear writing wins pitches |

Pick one non-coding role and learn the basics before the hackathon:
- Designer → Learn Figma in 2 days (YouTube tutorials)
- Presenter → Practice explaining a random project in 3 minutes
- Researcher → Learn how to do quick market research
- PM → Learn Notion or Trello basics

### If you have no team

- Look for "team formation" channels in the hackathon Discord
- Post: "First-time participant. Can contribute [your role]. Looking for a team."
- Join any team that will take you, even if the idea is not exciting
- Do not start a solo project for your first hackathon — you will burn out

## Phase 2: Foundation (Week 1-2)

### Step 2.1: Set up your environment
- Install VS Code (or use whatever editor you already have)
- Install Git and create a GitHub account
- Install Python (if using Python) or Node.js (if using JavaScript)
- Test that everything works by running "Hello World"

### Step 2.2: Build one small test project
Build something tiny but complete:
- Python: a CLI tool (to-do list, calculator, weather fetcher)
- JavaScript: a simple webpage that does one thing (counter, form, API display)
- Design: a Figma mockup of a mobile app screen

This is not for your hackathon. It is to confirm your tools work and you remember the basics.

### Step 2.3: Find and register for a beginner-friendly hackathon
Look for:
- **Online hackathons** (easier for first-timers)
- **Beginner-friendly tags** ("beginner friendly", "mentorship available", "first-timers welcome")
- **Longer duration** (48 hours is better than 24 hours for first time)
- **College-level** (less intimidating than national-level)

Platforms: Devfolio, Unstop, MLH (Major League Hacking).

### Step 2.4: Join the community
- Join the hackathon Discord/Slack/Telegram
- Introduce yourself in #introductions
- Read the announcements, rules, schedule
- Identify mentors and organizers

## Phase 3: Pre-hackathon preparation (2-3 days before)

### Step 3.1: Team check-in
- Have a 15-minute call with your team
- Agree on a rough idea (do not overthink — pick something simple)
- Assign roles: who codes what, who does the presentation
- Set up a WhatsApp group or Discord channel

### Step 3.2: Prepare templates and tools
- Create a GitHub repo for your project
- Set up basic project structure
- Prepare a slide template (Google Slides or Canva)
- If using APIs: test that they work with a sample call

### Step 3.3: Prepare logistically
- Charge everything (laptop, phone, power bank)
- Pack snacks, water bottle, hoodie
- Clear your schedule for the event duration
- Inform family that you will be busy

## Phase 4: The hackathon

### First 2 hours
- [ ] Finalize your idea (simple > ambitious. You can add features if time permits.)
- [ ] Divide work clearly
- [ ] Set up the project and start building
- [ ] Do not spend more than 30 minutes on idea selection

### Middle hours (Hours 3-16)
- [ ] Build the core feature first. Everything else is secondary.
- [ ] Ask mentors for help when stuck (this is what they are there for)
- [ ] Take a 10-minute break every 3 hours
- [ ] Eat when food is available (do not skip meals)
- [ ] Communicate with your team constantly

### Last 4 hours
- [ ] Freeze features. Do not start anything new.
- [ ] Fix the most critical bugs only
- [ ] Prepare your presentation
- [ ] Record a demo video (your live demo will probably break)
- [ ] Write your team name and project name on the submission

### Last hour
- [ ] Submit before the deadline (last-minute submissions crash)
- [ ] Confirm submission received
- [ ] Upload code to GitHub
- [ ] Celebrate that you finished

## Phase 5: After the hackathon

### Step 5.1: Rest
Sleep. Eat properly. Do not look at code for 24 hours.

### Step 5.2: Review
Write down:
- What did I build? (be specific about what worked and what did not)
- What did I learn technically?
- What did I learn about working in a team?
- What would I do differently next time?

### Step 5.3: Document
- Push final code to GitHub with a README
- Update your LinkedIn with the hackathon experience
- Connect with teammates and people you met
- Write a short LinkedIn post (does not need to be profound)

### Step 5.4: Decide on next steps
- Register for another hackathon within 1-2 months
- This time, you already know the format

## Common mistakes

| Mistake | Why it happens | Fix |
|---|---|---|
| Starting with an ambitious idea | Wanting to impress | Pick the simplest version of your idea |
| Not talking to mentors | Fear of looking stupid | Mentors have seen every level. They expect beginners. |
| Not sleeping | "Everyone else is awake" | Take 2-3 hours of sleep. You will work better after. |
| Team not communicating | Assuming everyone knows what to do | Over-communicate. Check in every 2 hours. |
| Building the presentation last minute | Running out of time | Leave 2 hours minimum for presentation prep |
| Comparing with other teams | Social pressure | Your only competition is your own learning |

## No-code participation path

If you cannot code and do not want to take a non-coding role:

1. Use **Bubble** or **Glide** to build a no-code web app
2. Use **FlutterFlow** (no-code mobile app builder)
3. Use **Zapier/Make** to create automations
4. Build the entire project as a well-designed Figma prototype
5. Present it as "design + user research + business model"

Many judging criteria include "innovation" and "impact" — not just "technical complexity." A well-thought-out no-code project beats a half-built coded project.

## Realistic outcomes table

| Effort level | Likely outcome |
|---|---|
| Showed up, built something basic, submitted | Successful participation. You learned the format. |
| Built something that mostly works | Strong first hackathon. Good for portfolio. |
| Built something that works + good presentation | Could place in top 20-30%. |
| Won a prize | Exceptionally good. But do not expect this. |
| Nothing worked, did not submit | Still learned what not to do. Try again. |
