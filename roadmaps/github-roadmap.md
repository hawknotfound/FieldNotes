# GitHub Roadmap

Use GitHub as a portfolio, learning archive, project showcase, and networking tool.

**Who this is for**: Students who have a GitHub account but do not use it effectively. Or students who have never used GitHub and need to start.

## Phase 1: Foundation (Week 1)

### Step 1.1: Create an account
If you do not have one, create a GitHub account. Username should be professional — firstname-lastname or firstname-lastname-initial is ideal. Avoid numbers or "gamer" handles.

### Step 1.2: Set up Profile README
Create a repository named `{your-username}` (exactly matching your username). Add a README.md with:

```
### Hi there 👋

I'm [Name], a [year] student at [college].

🔭 I build [what you build — web apps, AI tools, etc.]
🌱 Currently learning [current focus]
⚡ Looking to collaborate on [what you want to work on]

📫 Reach me: [LinkedIn] | [Email] | [Portfolio]
```

Add a profile stats image if you want (GitHub readme stats), but keep it clean. Less is more.

### Step 1.3: Learn basic Git
You need 5 commands to start:
- `git init` / `git clone`
- `git add .`
- `git commit -m "message"`
- `git push`
- `git pull`

That is enough for individual work. Learn branching later.

## Phase 2: Build your portfolio (Week 2-4)

### Step 2.1: Upload existing projects
If you have projects sitting on your laptop, put them on GitHub. Each project gets its own repository.

### Step 2.2: Write good READMEs

Every repository needs a README that answers:

```
# Project Name

## What it does
One paragraph explaining the project. Assume the reader knows nothing.

## Tech stack
- Frontend: React, Tailwind
- Backend: Node.js, Express
- Database: MongoDB
- APIs used: Google Maps API

## How to run
```bash
git clone https://github.com/yourusername/project
npm install
npm start
```

## What I learned
Challenges faced, problems solved, skills gained.

## Links
- Live demo: https://...
- Blog post: https://...
```

### Step 2.3: Pin your best work
Go to your profile, click "Customize your pins," and select 3-6 repositories that represent your best work. These appear at the top of your profile.

## Phase 3: Use GitHub as a learning archive (Week 3-8)

### Step 3.1: Document your learning
When you learn something new, create a repository for it:
- A tutorial you followed → push the code with your notes
- Notes on a topic → push them as a markdown file
- Practice problems → push solutions with explanations

This serves two purposes: it proves you can do the work, and it helps you revisit what you learned.

### Step 3.2: Commit regularly
- Commit at least 3-4 times per week
- Write meaningful commit messages:
  - Bad: `update`, `fix`, `changes`
  - Good: `Add user authentication flow`, `Fix date parsing bug on Safari`, `Refactor API route handlers`
- Consistent commits show recruiters you work consistently

### Step 3.3: Keep the contribution graph green
You do not need to code every day. But try to do something on GitHub 4-5 days a week. Documentation, planning, coding — all of it counts.

## Phase 4: Use GitHub as a networking tool (Week 6-12)

### Step 4.1: Star and follow
- Star repositories that you find useful or inspiring
- Follow developers whose work you admire
- Watch repositories you want to learn from

This builds your feed and helps GitHub recommend relevant content.

### Step 4.2: Contribute to open source (beginner level)
Start small:
1. Find repositories with labels `good-first-issue` or `help-wanted`
2. Read CONTRIBUTING.md before doing anything
3. Start with documentation fixes or small bug fixes
4. Engage in issues: ask clarifying questions before making changes

### Step 4.3: Make your profile discoverable
- Add GitHub link to your LinkedIn profile
- Add GitHub link to your resume
- Share your repositories on LinkedIn when you complete them
- Mention your GitHub in your professional introduction

| Platform | Where to put GitHub link |
|---|---|
| LinkedIn | Contact info section, Featured section |
| Resume | Links section, after name/contact |
| Email signature | Below your name |
| Portfolio | Footer or navigation |

### Step 4.4: Build in public
Share your development process, not just finished products:
- Create a repository for an idea you are exploring (even if incomplete)
- Open issues to document what you are planning to build
- Share your learning journey in README updates

Recruiters and collaborators are more interested in how you work than what you have finished.

## Phase 5: Maintain and grow (Ongoing)

### Monthly maintenance
- [ ] Review and archive old repos (unfinished, no longer relevant)
- [ ] Update Profile README if your focus has changed
- [ ] Update pinned repos to reflect your best current work
- [ ] Respond to issues or PRs on your repositories

### Quarterly review
- [ ] Update "About" section on your profile
- [ ] Refresh READMEs of pinned repos
- [ ] Check contribution graph — is it active?
- [ ] Identify 1-2 new open source projects to contribute to

## What recruiters look for

| Signal | What it communicates |
|---|---|
| Active commits (3+/week) | Consistency and dedication |
| Clean READMEs | Communication skills and documentation habit |
| Pinned projects aligned with target role | Relevant skills |
| Open source contributions | Collaboration ability |
| Well-structured code | Engineering discipline |
| Variety of projects | Broad capability and curiosity |

## Common mistakes

| Mistake | Fix |
|---|---|
| Pushing one large commit with "initial commit" | Commit incrementally as you build |
| Copied tutorial projects without changes | Modify them, add features, make them yours |
| No README or vague description | Write one that explains what the project does |
| Using "Delete this later" as repo names | Name repos descriptively |
| No commits for months | Set a weekly reminder to push something |
| Private repos as primary portfolio | Make your best repos public |
| Poor commit messages | Write messages that explain what changed and why |
| Cluttered profile with 50+ repos | Archive old ones, pin only your best |

## GitHub habit template

| Frequency | Action | Time |
|---|---|---|
| Daily | Code something, commit, push | 30+ min |
| Weekly | Write or update a README | 15 min |
| Weekly | Star 3-5 interesting repos | 5 min |
| Monthly | Review profile, update pins | 10 min |
| Monthly | Look for a good-first-issue to contribute | 20 min |
| Quarterly | Full profile audit and cleanup | 30 min |

## Quick start

1. Create account with professional username
2. Set up Profile README
3. Push one existing project with a good README
4. Pin it to your profile
5. Add GitHub link to LinkedIn
6. Commit something every 2 days for 2 weeks
