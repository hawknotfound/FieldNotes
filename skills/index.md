# Skills

Notes on building practical skills that help students participate in hackathons, competitions, and real-world projects.

## Why skills matter

- Most hackathons and competitions require more than textbook knowledge
- Employers and selectors look for demonstrated ability, not just marks
- Building projects teaches you more than any course

## Key skill areas for Indian students

| Skill | Why | Where to start |
|---|---|---|
| Programming | Hackathons, coding competitions, projects | Python, JavaScript, C++ |
| Web development | Build and deploy projects fast | HTML/CSS/JS, React, Node.js |
| UI/UX design | Make your projects look professional | Figma (free), basic design principles |
| Data structures & algorithms | Coding competitions, tech interviews | CP-Algorithms, LeetCode |
| Communication & pitching | Present your work effectively | Practice, feedback, recording yourself |
| Project management | Deliver on time in team settings | Notion, Trello, basic planning |
| Research skills | Understand domains you build for | Google Scholar, papers, blogs |

## Skill-building roadmap

### Month 1-2: Foundation
Pick one skill from the table above. Spend 2 months building a basic foundation. Do not multitask.
- 30 min/day for coding, 1 hour/day for others
- Follow a structured course or tutorial
- Build one small project to apply what you learned

### Month 3-4: Application
- Participate in an event that uses this skill
- Build a slightly larger project
- Share your work for feedback
- Fix issues based on feedback

### Month 5-6: Depth
- Learn advanced concepts in the same skill
- Teach someone else what you know
- Contribute to a project (open source or team)
- Participate in 2+ events using this skill

### Ongoing: Breadth
Once you have reasonable depth in one skill, start a second. The second skill takes half the time because you already know how to learn.

## How to approach skill-building

1. **Learn by doing** — build projects while learning
2. **Focus on one thing at a time** — depth before breadth
3. **Use free resources** — YouTube, documentation, open courses
4. **Build in public** — share your progress on LinkedIn/Twitter
5. **Teach others** — explaining solidifies understanding

## Resource recommendations per skill

| Skill | Best free resource | Best practice method |
|---|---|---|
| Programming | CS50 (Harvard/Youtube) | Build a CLI tool, then a web app |
| Web development | The Odin Project | Clone a real website, then build your own |
| UI/UX design | Figma tutorials + practice | Redesign an existing app screen daily |
| DSA | LeetCode + CP-Algorithms | Solve 1 problem/day, review solutions |
| Communication | Toastmasters + recording yourself | Pitch your project to 3 strangers |
| Project management | Notion + YouTube | Plan your next hackathon project formally |
| Research | Google Scholar tutorials | Read and summarize 1 paper/week |

## Common skill-building mistakes

- **Tutorial hell**: Watching tutorials without building. The fix: for every 1 hour of tutorial, spend 2 hours building.
- **Switching skills too fast**: Starting Python, then switching to JavaScript, then to design. The fix: commit to one skill for 2 months minimum.
- **Not building an audience**: Sharing your work forces clarity and builds accountability. The fix: post your progress, even if imperfect.
- **Avoiding hard parts**: Skipping debugging, skipping advanced topics, skipping feedback. The fix: do the part that feels hardest first.
- **Not finishing projects**: Starting 10 projects, finishing 0. The fix: finish one small project before starting the next.
